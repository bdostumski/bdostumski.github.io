* Vagrant Command Handbook:

*1. Vagrant Installation & Configuration*

#+BEGIN_SRC bash

# Check Vagrant version
vagrant --version
vagrant -v

# Display Vagrant help
vagrant help

# Display help for a specific command
vagrant help up
vagrant help provision

# Check Vagrant environment
vagrant version

# Display Vagrant home directory
echo $VAGRANT_HOME                 # Linux / macOS
echo %VAGRANT_HOME%               # Windows

# Set custom Vagrant home directory (Linux / macOS)
export VAGRANT_HOME=/path/to/vagrant

#+END_SRC

*2. Vagrant Project Initialization*

#+BEGIN_SRC bash

# Create project directory
mkdir vagrant-project
cd vagrant-project

# Initialize Vagrantfile
vagrant init

# Initialize with a specific box
vagrant init ubuntu/jammy64

# Initialize with a specific box version
vagrant init ubuntu/jammy64 --box-version 20241002.0.0

# Validate Vagrantfile syntax and configuration
vagrant validate

# Display project configuration
cat Vagrantfile

#+END_SRC

Note: `vagrant init` generates a Vagrantfile. The VM is not created until `vagrant up` is executed.

*3. Vagrant Box Management*

Boxes are reusable base images used to create virtual machines.

#+BEGIN_SRC bash

# Search for boxes

# Add a box
vagrant box add ubuntu/jammy64

# Add a specific box version

# List installed boxes

# Display box information
vagrant box list

# Check whether boxes are outdated
vagrant box outdated

# Check a specific box
vagrant box outdated --global

# Update boxes
vagrant box update

# Update a specific box
vagrant box update --box ubuntu/jammy64

# Remove a box
vagrant box remove ubuntu/jammy64

# Remove a specific box version
vagrant box remove ubuntu/jammy64 --box-version 20241002.0.0

#+END_SRC

Useful box commands:

| Command | Purpose |
| --- | --- |
| `vagrant box add` | Download and register a box |
| `vagrant box list` | List installed boxes |
| `vagrant box outdated` | Check for newer versions |
| `vagrant box update` | Update box used by an environment |
| `vagrant box remove` | Remove a local box |
| `vagrant cloud search` | Search available cloud boxes |

| --- | --- |

*6. Provisioning & Configuration Management*

Provisioning automates software installation and system configuration inside virtual machines.

#+BEGIN_SRC bash

# Run configured provisioners
vagrant provision

# Provision a specific machine
vagrant provision app

# Start VM and force provisioning
vagrant up --provision

# Restart VM and provision
vagrant reload --provision

# Run provisioners with a specific provisioner name
vagrant provision --provision-with shell

# Run multiple provisioners
vagrant provision --provision-with shell,ansible

#+END_SRC

Example shell provisioner:

#+BEGIN_SRC ruby

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  config.vm.provision "shell", inline: <<-SHELL
    apt-get update
    apt-get install -y nginx
    systemctl enable nginx
    systemctl start nginx
  SHELL
end

#+END_SRC

Example external shell script:

#+BEGIN_SRC ruby

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  config.vm.provision "shell",
    path: "scripts/bootstrap.sh"
end

#+END_SRC

Useful provisioning options:

| Option | Purpose |
| --- | --- |
| `inline` | Execute an inline script |
| `path` | Execute an external script |
| `privileged` | Run with elevated privileges |
| `run: "always"` | Run provisioner on every applicable provisioning run |
| `run: "once"` | Run provisioner only once during initial creation |
| `name` | Identify a provisioner |

#+BEGIN_SRC bash

# Forward guest port 80 to host port 8080

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

Additional networking examples:

# Forward application port

  guest: 8080,

  guest: 22,
  host: 2222

# Private network with static IP
config.vm.network "private_network",
  ip: "192.168.56.10"

# Private network with DHCP
config.vm.network "private_network",
  type: "dhcp"

# Public / bridged network
config.vm.network "public_network"

#+END_SRC

Useful networking options:

| Option | Purpose |
| --- | --- |
| `forwarded_port` | Forward host traffic to guest |
| `private_network` | Create a private network |
| `public_network` | Connect VM to an external network |
| `guest` | Guest VM port |
| `host` | Host machine port |
| `ip` | Assign a static IP address |
| `auto_correct` | Automatically resolve host port conflicts |

Note: Public networks can expose VMs to other devices on the network. Use them carefully.

*9. Provider Configuration – VirtualBox, VMware & Hyper-V*

Vagrant supports multiple virtualization providers.

#+BEGIN_SRC bash

# Start with VirtualBox
vagrant up --provider=virtualbox

# Start with VMware
vagrant up --provider=vmware_desktop

# Start with Hyper-V
vagrant up --provider=hyperv

#+END_SRC

VirtualBox configuration:

#+BEGIN_SRC ruby

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  config.vm.provider "virtualbox" do |vb|
    vb.name = "development-vm"
    vb.memory = 4096
    vb.cpus = 2
    vb.gui = false
  end
end

#+END_SRC

VMware configuration:

#+BEGIN_SRC ruby 

config.vm.provider "vmware_desktop" do |v|
  v.vmx["memsize"] = "4096"
  v.vmx["numvcpus"] = "2"
end

#+END_SRC

Hyper-V configuration:

#+BEGIN_SRC ruby 

config.vm.provider "hyperv" do |h|
  h.memory = 4096
  h.cpus = 2
end

#+END_SRC

Provider resource options:

| Option | Purpose |
| --- | --- |
| `memory` | Allocate VM RAM |
| `cpus` | Allocate virtual CPUs |
| `gui` | Enable or disable graphical interface |
| `name` | Set VM name |
| `--provider` | Select virtualization provider |

Note: Provider-specific settings are not interchangeable. Verify that the provider supports each option.

*10. Multi-Machine Environments*

Vagrant can manage multiple coordinated virtual machines using a single Vagrantfile.

#+BEGIN_SRC bash

# Start all machines
vagrant up

# Start database machine
vagrant up db

# Start application machine
vagrant up app

# Check all machine statuses
vagrant status

# Connect to database machine
vagrant ssh db

# Connect to application machine
vagrant ssh app

# Provision a specific machine
vagrant provision db

# Stop all machines
vagrant halt

# Destroy all machines
vagrant destroy

#+END_SRC

Example multi-machine Vagrantfile:

#+BEGIN_SRC ruby

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  config.vm.define "db" do |db|
    db.vm.hostname = "db.local"
    db.vm.network "private_network",
      ip: "192.168.56.10"

    db.vm.provider "virtualbox" do |vb|
      vb.memory = 1024
      vb.cpus = 1
    end
  end

  config.vm.define "app" do |app|
    app.vm.hostname = "app.local"
    app.vm.network "private_network",
      ip: "192.168.56.11"

    app.vm.network "forwarded_port",
      guest: 8080,
      host: 8080

    app.vm.provider "virtualbox" do |vb|
      vb.memory = 2048
      vb.cpus = 2
    end
  end
end

#+END_SRC

Useful multi-machine commands:

| Command | Purpose |
| --- | --- |
| `vagrant up db` | Start database VM |
| `vagrant up app` | Start application VM |
| `vagrant ssh db` | Connect to database |
| `vagrant provision app` | Provision application VM |
| `vagrant halt` | Stop all machines |
| `vagrant destroy` | Destroy all machines |

  --vagrantfile Vagrantfile

#+END_SRC

Custom box workflow:

#+BEGIN_SRC bash

# Start and configure VM
vagrant up

# Install required packages

*15. Security & SSH Configuration*

#+BEGIN_SRC ruby

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  # Enable unique SSH key insertion
  config.ssh.insert_key = true

  # Configure SSH username
  config.ssh.username = "vagrant"

  # Configure SSH connection timeout
  config.ssh.connect_timeout = 30

  # Disable SSH agent forwarding unless needed
  config.ssh.forward_agent = false
end

#+END_SRC

Security recommendations:

- Use trusted and maintained base boxes.
- Pin box versions for reproducible environments.
- Avoid committing passwords, private keys, or tokens.
- Use least-privilege provisioning.
- Restrict forwarded ports and public network exposure.
- Avoid exposing SSH or application debugging ports to untrusted networks.
- Update base boxes regularly.
- Review third-party plugins before installing them.

*20. Best Practices for Technical Leads & DevOps*

1. Keep the Vagrantfile under version control.
2. Use trusted and version-pinned base boxes.
3. Automate all environment setup through provisioning.
4. Prefer idempotent provisioning scripts.
5. Keep provisioning logic modular and maintainable.
6. Avoid manual configuration changes inside running VMs.
7. Use appropriate CPU and memory allocations.
8. Minimize unnecessary forwarded ports.
9. Prefer private networking for internal VM communication.
10. Avoid exposing SSH and debugging ports publicly.
11. Use secure secret-management mechanisms.
12. Test environments from a clean state regularly.
13. Use snapshots for short-term recovery, not as a backup strategy.
14. Keep plugins updated and review their security.
15. Use consistent provider configurations across development teams.
16. Automate VM creation and destruction in CI/CD where appropriate.
17. Monitor resource consumption and synced-folder performance.
18. Document common Vagrant commands and troubleshooting procedures.
19. Treat development VMs as disposable infrastructure.
20. Ensure every developer can reproduce the environment from the Vagrantfile and provisioning code.

* Beginner

** Q1: What is Vagrant?
Vagrant is a tool for building and managing reproducible virtualized development environments.

** Q2: Why use Vagrant?
It standardizes local environments and reduces “works on my machine” problems.

** Q3: What is a Vagrant box?
A packaged base VM image used to create Vagrant machines.

** Q4: What file defines a Vagrant environment?
=Vagrantfile=.

** Q5: What language is Vagrantfile written in?
Ruby-based DSL.

** Q6: What does =vagrant init= do?
Creates a starter Vagrantfile.

** Q7: What does =vagrant up= do?
Creates and starts configured VM(s).

** Q8: What does =vagrant ssh= do?
SSH into running Vagrant VM.

** Q9: What does =vagrant halt= do?
Gracefully stops VM.

** Q10: What does =vagrant reload= do?
Restarts VM and reapplies Vagrantfile config (as needed).

** Q11: What does =vagrant destroy= do?
Deletes VM instance resources.

** Q12: What does =vagrant suspend= do?
Pauses VM, preserving memory state.

** Q13: Suspend vs halt?
Suspend saves runtime state; halt performs full shutdown.

** Q14: What does =vagrant status= show?
Current state of managed machine(s).

** Q15: What does =vagrant provision= do?
Runs configured provisioners on VM.

** Q16: What is a provider in Vagrant?
Backend virtualization platform (VirtualBox, VMware, Hyper-V, libvirt, etc.).

** Q17: Is Vagrant itself a hypervisor?
No, it orchestrates existing providers/hypervisors.

** Q18: What is provisioning?
Automated setup of software/configuration inside VM.

** Q19: Common provisioners in Vagrant?
Shell, Ansible, Chef, Puppet (and others/plugins).

** Q20: What is synced folder?
Folder shared between host and guest VM.

** Q21: Why synced folders useful?
Edit code on host, run it inside VM environment.

** Q22: Default synced folder path in guest?
Typically =/vagrant=.

** Q23: What is forwarded port?
Maps host port to guest port.

** Q24: Why use port forwarding?
Access guest services from host browser/tools.

** Q25: What is private network in Vagrant?
Host-only network between host and guest(s).

** Q26: What is public network in Vagrant?
Bridged network exposing VM on external LAN.

** Q27: Why be careful with public networks?
They increase exposure to external network threats.

** Q28: What is multi-machine Vagrant setup?
Single Vagrantfile defining multiple coordinated VMs.

** Q29: Why use multi-machine?
Simulate distributed systems locally (app/db/cache clusters).

** Q30: What is box versioning?
Using specific box versions for reproducibility.

** Q31: Why pin box versions?
Avoid unexpected changes from box updates.

** Q32: What does =vagrant box add= do?
Downloads/registers box locally.

** Q33: What does =vagrant box list= do?
Lists installed local boxes.

** Q34: What does =vagrant box remove= do?
Removes local box copy.

** Q35: What is =config.vm.box=?
Sets base box name in Vagrantfile.

** Q36: What is =config.vm.hostname=?
Sets VM hostname.

** Q37: What is =config.vm.provider= block?
Provider-specific resource/settings customization.

** Q38: How set VM memory/CPU?
Provider-specific config in Vagrantfile.

** Q39: What is idempotent provisioning?
Provisioning that can run multiple times safely.

** Q40: Why idempotency matters?
Reliable reprovisioning and reduced environment drift.

** Q41: What is Vagrant plugin?
Extension adding capabilities to Vagrant.

** Q42: How list plugins?
=vagrant plugin list=.

** Q43: What is common beginner Vagrant anti-pattern?
Manual in-VM changes not captured in provisioning scripts.

** Q44: Why avoid manual drift?
Destroys reproducibility and team consistency.

** Q45: What is box trust concern?
Untrusted boxes may contain insecure/malicious configurations.

** Q46: Beginner security baseline?
Use trusted boxes, SSH keys, and least-exposed networking.

** Q47: Beginner performance baseline?
Allocate reasonable CPU/RAM and avoid heavy unnecessary services.

** Q48: What is snapshot concept (provider-dependent)?
Save VM state checkpoint for quick restore.

** Q49: Why snapshots useful?
Fast recovery during experiments.

** Q50: What is =vagrant global-status=?
Shows VMs across all Vagrant environments on host.

** Q51: What is VAGRANT_HOME?
Directory storing global Vagrant data/boxes/plugins.

** Q52: Why keep Vagrantfile in version control?
Team-shared environment definition and change history.

** Q53: Beginner testing baseline?
Bring environment up from scratch regularly to verify reproducibility.

** Q54: Beginner operations principle?
Automate everything needed after =vagrant up=.

** Q55: Beginner best practice?
Treat Vagrant environments as disposable and fully scripted.

* Intermediate

** Q56: What is provisioning order in Vagrant?
Provisioners run in configured sequence; order affects final state.

** Q57: Why split provisioning into stages?
Improves clarity, reuse, and troubleshooting.

** Q58: Inline shell vs external script provisioner?
Inline for small tasks; external scripts for maintainability.

** Q59: What is privileged shell provisioning?
Runs script with elevated privileges (root/admin).

** Q60: Why limit privileged provisioning?
Reduce security risk and accidental system-wide changes.

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"

  config.vm.define "db" do |db|
    db.vm.hostname = "db.local"
    db.vm.network "private_network", ip: "192.168.56.10"
    db.vm.provider "virtualbox" do |vb|
      vb.memory = 1024
      vb.cpus = 1
    end
    db.vm.provision "shell", inline: <<-SHELL
      apt-get update
      apt-get install -y postgresql
    SHELL
  end

  config.vm.define "app" do |app|
    app.vm.hostname = "app.local"
    app.vm.network "private_network", ip: "192.168.56.11"
    app.vm.network "forwarded_port", guest: 8080, host: 8080
    app.vm.provider "virtualbox" do |vb|
      vb.memory = 2048
      vb.cpus = 2
    end
    app.vm.provision "shell", inline: <<-SHELL
      apt-get update
      apt-get install -y openjdk-21-jre
    SHELL
  end
end
