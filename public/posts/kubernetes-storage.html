Common access modes:

Access Mode Meaning
RWO ReadWriteOnce – read/write mounting from one node
ROX ReadOnlyMany – read-only mounting from multiple nodes
RWX ReadWriteMany – read/write mounting from multiple nodes
RWOP ReadWriteOncePod – read/write mounting by a single Pod

Note: Access modes describe supported mounting capabilities, not application-level locking or data consistency. Actual support depends on the storage driver.

# Check StorageClass expansion support
kubectl get sc storage-class-name \
  -o jsonpath='{.allowVolumeExpansion}'

kubectl patch pvc my-pvc \
  -p '{"spec":{"resources":{"requests":{"storage":"20Gi"}}}}'

kubectl describe pvc my-pvc

# Watch PVC resizing
kubectl get pvc my-pvc -w

# Display PV capacity
kubectl get pv

# Check resize-related events
kubectl get events --sort-by=.metadata.creationTimestamp

Note: PVC expansion requires StorageClass support and a compatible CSI driver. Filesystem expansion may happen online or require a Pod restart, depending on the driver and filesystem.

10. PersistentVolume Reclaim Policies 


# Display PV reclaim policy
kubectl get pv my-pv \
  -o jsonpath='{.spec.persistentVolumeReclaimPolicy}'

# Display StorageClass reclaim policy
kubectl get sc storage-class-name \
  -o jsonpath='{.reclaimPolicy}'

# Change PV reclaim policy to Retain
kubectl patch pv my-pv \
  -p '{"spec":{"persistentVolumeReclaimPolicy":"Retain"}}'

# Change PV reclaim policy to Delete
kubectl patch pv my-pv \
  -p '{"spec":{"persistentVolumeReclaimPolicy":"Delete"}}'

# Check PV status
kubectl get pv

# Inspect released PV
kubectl describe pv my-pv

# List PVCs
kubectl get pvc -A

Reclaim policies:

Policy Behavior
Retain Keeps underlying storage for manual recovery
Delete Deletes the underlying storage resource when supported
Recycle Deprecated legacy behavior; do not use for new workloads

Important: Changing a reclaim policy does not restore deleted data. Verify storage-backend behavior and backups before deleting PVCs or PVs.

12. Creating & Restoring Volume Snapshots 


# Apply snapshot manifest
kubectl apply -f volumesnapshot.yaml

# Monitor snapshot creation
kubectl get volumesnapshots -w

# Describe snapshot
kubectl describe volumesnapshot db-snapshot

# Check snapshot readiness
kubectl get volumesnapshot db-snapshot

# Restore PVC from snapshot
kubectl apply -f restore-pvc.yaml

# Monitor restore operation
kubectl get pvc -w

# Verify restored PVC
kubectl describe pvc restored-pvc

# Mount restored PVC into a test Pod
kubectl apply -f restore-test-pod.yaml

# Verify restored data
kubectl exec restore-test-pod -- ls -la /data

Example VolumeSnapshot: 


apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshot
metadata:
  name: db-snapshot
spec:
  volumeSnapshotClassName: csi-snapshot-class
  source:
    persistentVolumeClaimName: db-pvc

Example PVC restored from a snapshot: 


apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: restored-pvc
spec:
  storageClassName: standard
  dataSource:
    name: db-snapshot
    kind: VolumeSnapshot
    apiGroup: snapshot.storage.k8s.io
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi

Note: The CSI snapshot controller, snapshot CRDs, and a compatible CSI driver must be installed. The requested restore capacity must be compatible with the snapshot's source volume and driver.

  name: local-pv

  volumeMode: Filesystem

    - ReadWriteOnce

  storageClassName: local-storage

    path: /mnt/disks/vol1

Common storage problems:

Error / Status Possible Cause
`Pending` PVC No compatible PV or provisioning failure
`Lost` PVC Bound PV is no longer available
`FailedMount` Volume mount or backend failure
`FailedAttachVolume` Volume attachment failure

Important Storage Best Practices:

  1. Use PVCs and StorageClasses instead of coupling applications directly to storage backends.
  2. Use dynamic provisioning where appropriate.
  3. Choose access modes according to the capabilities of the storage driver.
  4. Use `WaitForFirstConsumer` when topology-aware provisioning is required.
  5. Configure reclaim policies carefully to avoid accidental data deletion.
  6. Take regular backups and test restoration procedures.
  7. Use volume snapshots as one part of a complete backup strategy.
  8. Monitor PVC capacity, disk usage, IOPS, and storage latency.
  9. Encrypt sensitive data at rest and protect access to storage resources.
  10. Use StatefulSets and dedicated PVCs for workloads requiring stable storage identity.
  11. Validate storage expansion and recovery procedures before production use.

  12. Never assume that deleting a Pod, PVC, or StatefulSet has the same effect on the underlying data.

Beginner

Q1: What is Kubernetes storage?

Kubernetes storage is the infrastructure that provides durable or temporary file storage for workloads running in Pods.

Q2: Why does Kubernetes need storage?

Containers are ephemeral, and many applications need data that survives container restarts and rescheduling.

Q3: What is ephemeral storage?

Ephemeral storage is temporary storage local to a container or pod and usually lost when the pod is deleted.

Q4: What is persistent storage?

Persistent storage remains available across pod restarts and may outlive the pod itself.

Q5: What is a volume in Kubernetes?

A volume is a storage unit mounted into a pod, such as a directory or block device.

Q6: What is a pod volume?

A pod volume is a storage object attached to a pod and shared by one or more containers in that pod.

Q7: What are examples of Kubernetes volume types?

Examples include emptyDir, hostPath, configMap, secret, persistentVolumeClaim, and CSI-based volumes.

Q8: What is emptyDir?

emptyDir is a temporary volume created when a pod starts and deleted when the pod ends.

Q9: Why use emptyDir?

It is useful for scratch space, caches, and temporary data within a single pod.

Q10: What is a hostPath volume?

A hostPath volume mounts a file or directory from the node filesystem into the pod.

Q11: Why is hostPath risky?

It tightly couples the pod to the node filesystem and can expose host data or create security problems.

Q12: What is a ConfigMap volume?

A ConfigMap volume mounts configuration data as files into a pod.

Q13: What is a Secret volume?

A Secret volume mounts sensitive data into a pod as files with restricted access.

Q14: Why do pods need storage for logs?

Logs may need to be retained or shipped to a centralized system, even after pod restarts.

Q15: What is a StatefulSet?

A StatefulSet is a Kubernetes workload designed for stateful applications requiring stable identities and persistent storage.

Q16: Why are StatefulSets important for storage?

Because they often manage pods whose storage should survive rescheduling and identity changes.

Q17: What is a PersistentVolume?

A PersistentVolume (PV) is cluster-level storage resource provisioned by an administrator or storage system.

Q18: What is a PersistentVolumeClaim?

A PersistentVolumeClaim (PVC) is a request by a workload for storage with certain capacity and access mode.

Q19: What is the relation between PVC and PV?

A PVC binds to a compatible PV so a pod can use the storage.

Q20: Why use PVCs?

Because they abstract the storage backend and let workloads request storage declaratively.

Q21: What is a storage class?

A StorageClass defines the storage provisioner and policy, such as performance or reclaim behavior.

Q22: Why use a StorageClass?

It allows dynamic provisioning of PVs without manual cluster administration.

Q23: What is dynamic provisioning?

Dynamic provisioning automatically creates a PV when a PVC requests storage.

Q24: What is static provisioning?

Static provisioning means an admin manually creates a PV before a pod requests it.

Q25: What is a provisioner?

It standardizes how storage systems integrate with Kubernetes.

Q34: What is ReadOnlyMany?

ROX means the volume may be mounted read-only by many nodes.

RWX means the volume can be mounted read-write by many nodes.

Q37: What is a persistent volume claim binding?

A reclaim policy defines what happens to the underlying storage when a PV is released, such as Retain, Delete, or Recycle.

Q39: What is Retain?

Retain keeps the data on the underlying storage after the PV is released.

Q40: What is Delete?

Delete deletes the underlying storage resource when the PV is released.

Q41: What is Retain vs Delete in practice?

Retain preserves data for later recovery, while Delete removes the underlying storage automatically.

The reclaim policy in a StorageClass defines the default behavior for PVs created from that class.

Q44: Why are volume claim templates used in StatefulSets?

Because each pod replica often needs its own persistent volume.

Q45: What is a StatefulSet pod identity?

StatefulSet pods have stable names and identities, often used with persistent storage.

Q46: What is a pod restart vs volume loss?

A pod restart may keep the same PVC and thus the same data, while an image or ephemeral volume may be lost.

Q47: What is application state?

Application state includes user data, databases, caches, logs, and other durable artifacts.

Q48: Why is stateful application storage different from stateless app storage?

Stateful workloads need persistent data; stateless workloads can be recreated from immutable images.

Q49: What is a database volume?

Because database data must survive container restarts and node failures in many setups.

A block device volume exposes storage as a raw block device rather than a directory.

Q53: Why use block storage?

Some databases and storage systems need block semantics rather than file semantics.

Q54: What is local storage?

Local storage is storage local to a node, often not portable across machines.

Q55: Why are local volumes sometimes risky?

Because if the node fails, the data may be lost or unavailable.

Q56: What is a distributed storage system?

Distributed storage spans multiple nodes or storage clusters and can survive node failures.

Q57: What is network-attached storage?

A network-attached storage system is accessed over the network, often by NFS or block protocols.

Q58: What is cloud storage?

Cloud storage includes services like EBS, Azure Disk, or GCP Persistent Disk.

The capacity is the requested storage size, such as 10Gi.

A PV size is the actual amount of storage the storage backend provides.

Q61: Why does capacity matter?

Because workloads must be provisioned with enough space to operate reliably.

Q62: What is volume expansion?

Volume expansion increases the size of an existing persistent volume or claim.

It allows workloads to grow without redeploying or recreating the storage.

Q64: What is a data migration?

Q65: What is backup and restore for Kubernetes storage?

Q67: Why are snapshots useful?

Q73: What is a storage plugin?

Because it defines performance, durability, multi-attach behavior, and availability.

Some workloads need high IOPS or low latency, while others can use cheaper or slower storage.

Q77: What is ephemeral volume data?

Q78: What is persisted volume data?

Data on a PV or other durable backend that remains after pod restarts or reschedules.

Q79: What is a persistent data pipeline?

Q80: What is data locality?

Data locality is the principle of keeping computation near the data to reduce latency and cost.

Because remote storage can add latency and operational complexity.

Q88: What is a block-based app workload?

Each stateful microservice may use separate PVCs or storage classes based on needs.

Q90: What is a stateful service?

A stateful service depends on persistent data and stable identity.
